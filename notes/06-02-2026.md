            - [ChatVis GitHub](https://github.com/tpeterka/ChatVis)
            - ChatVis is an agent for Paraview visualization that takes data and
              natural language as an input and generates a Python script to
              visualize the data in either of these tools
            - MyCrunchGPT, LM4HPC, HPC-GPT, and HPC-Coder are relevant agents

                - Delaunay Triangulation
                - Streamline tracing
                - View parameter definition
            - ChatViz leverages a single LLM to generate the code with recursive
              reasoning on Paraview Python (`pvpython`) error outputs
            - Interface methodology
                - Given a system prompt plus the users prompt, the LLM (OpenAI
                  GPT-4) generates a new prompt specifying operations including
                    - file reading

            - Globus Flows Overview
                - Flows are used to orchestrate workflows
                - Can call both Globus and HTTP API services
                - Flows can call other flows
                - Flows can call Globus compute functions
                - [Example flows](https://github.com/globus/globus-flows-trigger-examples)
            - Globus Compute Overview
                - Compute is used to register Python functions that take
                  arguments as input and primarily process some data
                - Each function is registered to the cloud, but executed on
                  **connected local machines** allowing anyone to run code on
                  HPC systems so long as the system is availible
                - [Example compute functions](https://github.com/globus-labs/globus-compute-golf-demo)

#### Paraview MCP Docs Tooling

**Technical Pros**: - There is already a push to develop MCP tooling both at LUC
and ANL, so support is generally favorable - Should be relatively easy to
implement a prototype with Argo + OpenCode - Nick already has some experience
setting up and using RAG based solutions **Techinical Cons**: - ChatViz is not a
Viz. team project and any work that builds off of it would need aproval from
additional stakeholders - There is not a clearly defined benchmark or goal of
this work yet and seems to mostly boil down to which version produces the best
code without modifying the existing ChatViz methodology extensively - This would
be a plugin for ChatViz and that doesn't sound exciting on a first pass

**Academic Pros** - This work is low-hanging fruit and would be a valuable
contribution to scientists and RSEs - This would be a stepping stone work to
further work on wrapping scientific tooling into MCP servers and services -
Kitware could derive value from this in order to make their tooling more AI
friendly **Academic Cons** - This is a difficult work to get into EduHPC as
currently described - To add an education component to this would require
additional scaffolding to educate practicioners on the differences and benefits
between the two different versions of the knowledge base

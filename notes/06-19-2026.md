## Notes From Yesterday

06-18-2026 I focused on creating a slide deck to focus the research direction of
my project. What it effectively boils down to is rather than inventing a new
component to enable alternative ParaView agent integration, we are going to take
the best from 4 different methods and glue them together in a hierarchical
fashion. In doing so, we will be able to leverage the best of all methods while
patching limitations in each. The four methods under consideration are the
following:

- ChatVis
    - Includes both [V1](https://doi.org/10.1109/SCW63240.2024.00014) and
      [V2](https://doi.org/10.48550/arXiv.2507.23096) of this system
- [ParaView-MCP](https://doi.org/10.48550/arXiv.2505.07064)
- [SciVisAgentSkills](https://doi.org/10.48550/arXiv.2606.05525)
- [DocPrompting](https://openreview.net/forum?id=ZTCxT2t2Ru)

### Proposed Architecture

The following figure is a loose visualization of the proposed project
architecture: ![](week1_proposal.png) Here are the core components of this
architecture mapped to the best features of each previous system:

1. The user provides a prompt pointing to a specific scientific data file or
   directory (basic pattern used in all systems)
2. The headers of a `SKILL.md` file is loaded behind the scenes by the Coding
   agent. The content of this file contains direct code snippets from the latest
   version of ParaView and some common use cases, plus pointers to specific MCP
   services described later on
    1. `SKILL.md` comes from SciVisAgentSkills, the content of which comes from
       a combination of SciVisAgentSkills and ChatVis V1
3. A Coding Agent (e.g., Opencode, Claude Code, Codex) ingests this prompt and
   decides whether or not it needs to use the Skill. If so, it loads the file
   into its context
    1. Coding Agents became normalized via SciVisAgentBench, ParaView-MCP, and
       SciVisAgentSkills
4. ParaView code is generated. This can be accomplished by directly pulling from
   the `SKILL.md` file, or by connecting to a MCP service hosting a RAG database
   of the ParaView documentation
    1. RAG over ParaView documentation is a new contribution
    2. RAG integration comes from ChatVis V2
    3. MCP comes from ParaView-MCP and SciVisAgentBench
5. Post code generation, the ParaView code is sent to another MCP service for
   executing the code on a headless instance of ParaView. `stdout`, `stderr`,
   and the resulting visualization are returned to the model. Additionally, the
   user can connect to the remote instance to monitor the current status of the
   visualization.
    1. This is the best feature of ParaView-MCP
6. The Coding Agents implicit loop will iterate upon this until ParaView returns
   a visualization with no errors and the model thinks that this best matches
   the user's prompt

### Problems Identified

The following are missing features that if not implemented would significantly
impact the usability of this project:

- User prompt validation
    - How do we guarantee that the prompt the user submits is relevant to
      ParaView?
        - What if its not?
    - How do we validate that we have access to the input data?
    - How do we validate that we can write to the output directory?
- Coding Agent subagents
    - Do we utilize the plan mode in some coding agents?
    - What if a coding agent does not have a plan mode?
    - What if we want to implement a subagent to manipulate the user prompt?
- MCP Connections
    - How do we validate MCP inputs from the model?
